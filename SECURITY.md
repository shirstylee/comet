# Безопасность

## Сообщить об уязвимости

Не публикуйте ключи, пароли, личные данные или рабочие примеры эксплуатации
в публичных Issues и Pull Requests. Если в разделе Security репозитория доступна
кнопка **Report a vulnerability**, отправьте приватный отчёт через неё.
Если приватные отчёты недоступны, создайте Issue только с просьбой предоставить
приватный канал связи, без технических подробностей уязвимости.

## Секреты и сборки

- Передавайте собственный ключ RAWG через `--dart-define-from-file` или
  `--dart-define`. Пример без секрета находится в `config/dart-defines.example.json`.
- `config/dart-defines.json`, `.env*`, `android/key.properties` и файлы ключей
  подписи должны оставаться вне Git.
- Параметры `dart-define` исключают ключ из исходников, но не шифруют его
  внутри APK. Ключ в распространяемом клиенте можно извлечь. Для защиты
  общего ключа понадобится сервер-посредник.
- Не прикладывайте пользовательские экспорты, базы Hive и личные изображения
  к Issues и Pull Requests. Профиль и библиотека хранятся локально на устройстве.
- Если секрет попал в коммит, сначала отзовите или замените его у провайдера.
  Удаление строки из последнего коммита не удаляет её из истории Git.
