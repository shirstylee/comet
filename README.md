## ☄️ Описание

**Comet** — мобильное приложение на Flutter для ведения личной библиотеки игр.

Приложение помогает искать игры, добавлять их в коллекцию, отслеживать прохождение, ставить оценки и хранить собственные впечатления.

---

## 📱 О проекте

Comet создан как курсовой проект по разработке мобильных приложений.

Основная идея приложения — дать пользователю удобный игровой дневник, где можно хранить свою коллекцию игр и следить за прогрессом прохождения.

Приложение выполнено в тёмном космическом стиле с акцентными голубыми цветами.

Поддерживаемая платформа — **Android 9 (API 28) и новее**. Текущая версия — **1.0.0**.
Профиль, библиотека и прогресс хранятся на устройстве; для поиска игр и загрузки
материалов RAWG нужен интернет. Реализованы экспорт и импорт резервной копии.

## 📂 Основные разделы приложения

### Главная

На главном экране отображается краткая статистика пользователя, недавняя активность и быстрый переход к добавлению игры.

### Игры

Раздел библиотеки, где пользователь видит все добавленные игры, может фильтровать их по статусу и открывать подробную информацию о прохождении.

### Поиск

Поиск игры по названию через RAWG API с возможностью открыть подробную информацию и добавить игру в коллекцию.

### Оценки

Экран со статистикой пользовательских оценок, средним рейтингом и списком недавно оценённых игр.

### Профиль

Профиль пользователя с аватаром, статусом, игровой статистикой, избранной игрой и последними отзывами.

## 🚀 Запуск из исходников

Инструкции предназначены для автора и пользователей, получивших разрешение
на использование кода. Условия указаны в [LICENSE](LICENSE).

### Требования

- Flutter **3.41.6** (Dart **3.11.4**) — версия SDK, закреплённая в CI.
- Android SDK и Java **25 LTS** (Java **17** также проверяется в CI).
- Эмулятор или устройство с Android **9+**.
- Собственный ключ [RAWG API](https://rawg.io/apidocs).

Сборка использует Gradle **9.3.1**, Android Gradle Plugin **8.13.2** и Kotlin
**2.3.21**. Java 25 поддерживается сборщиком; целевой уровень Java/Kotlin-кода
остаётся **17**, а минимальная версия Android — **9 (API 28)**. Android 10
поддерживается; установка новой Java на телефон не требуется.

Выберите установленную JDK 25 для Flutter:

```sh
flutter config --jdk-dir="путь к JDK 25"
```

На Windows, если Android Studio содержит JBR 25, можно указать
`C:\Program Files\Android\Android Studio\jbr`. Версию проверьте командой
`flutter doctor -v`: при обновлении Android Studio её встроенная Java может
измениться. Поддержка Java 26 и будущих версий здесь не заявлена.
Настройка `flutter config --jdk-dir` действует для **всех локальных Flutter-проектов**.
Для сборки из Android Studio выберите ту же JDK в настройках **Gradle JDK**.

Проверьте окружение и получите зависимости:

```sh
git clone https://github.com/shirstylee/Comet.git
cd Comet
flutter doctor
flutter pub get
```

Скопируйте `config/dart-defines.example.json` в `config/dart-defines.json`
и заполните поле `RAWG_API_KEY` своим ключом. Новый файл исключён из Git.

```sh
flutter run --dart-define-from-file=config/dart-defines.json
```

В Android Studio добавьте этот же аргумент в **Additional run args** конфигурации
Flutter. После изменения ключа полностью перезапустите приложение: hot reload
не обновляет параметры сборки.

Без ключа приложение запускается, но поиск и обновление сведений из RAWG недоступны.
Ключи передаются через [параметры компиляции Dart](https://dart.dev/libraries/core/environment-declarations),
а не записываются в `lib/config/api_keys.dart`. Они остаются извлекаемыми из
собранного приложения; подробнее — в [SECURITY.md](SECURITY.md).

### Сборка Android

Для локальной отладки приватный ключ подписи не нужен:

```sh
flutter build apk --debug --dart-define-from-file=config/dart-defines.json
```

APK появится в `build/app/outputs/flutter-apk/app-debug.apk`.

Для release-сборки создайте собственное хранилище ключей по
[инструкции Flutter](https://docs.flutter.dev/deployment/android#sign-the-app),
скопируйте `android/key.properties.example` в `android/key.properties` и заполните
параметры подписи. Путь `storeFile` отсчитывается от `android/app`; на Windows
удобно использовать прямые слеши. Release без настроенной подписи завершится
понятной ошибкой.

```sh
flutter build apk --release --dart-define-from-file=config/dart-defines.json
```

Release APK: `build/app/outputs/flutter-apk/app-release.apk`.
Не добавляйте файлы настроек, хранилища ключей и сборки в Git.

## ✅ Проверки

```sh
flutter analyze --no-fatal-infos
flutter test
flutter build apk --debug
```

[GitHub Actions](.github/workflows/flutter.yml) выполняет эти проверки на Java
**17 и 25** при push и pull request. Тесты используют подставные ответы RAWG;
секреты для CI не нужны.
Отладочная сборка в CI проверяет компиляцию и не содержит рабочего ключа API.

В коде пока есть информационные замечания анализатора, в том числе об устаревшем
`withOpacity`. Они видны в выводе, но не блокируют CI. Ошибки и предупреждения
анализатора, а также ошибки тестов и сборки блокируют проверку.
